# SaskHandy 2.0 release contract
Source baseline: 8838183eca1b7278ba06daeeaddf6b59457e4687. One coordinated release, no independent production feature deployments.

## Product standard
Home projects. Made simple. Clear Canadian English, customer-facing quotes and requests, actionable errors. Inter, selective DM Serif Display, forest green, consistent spacing, accessible layouts, one primary action. Never invent reviews, activity, pricing or availability.

## Implemented in initial branch changes
Request-first homepage, same-tab sign-in handoff, removal of unverified hardcoded testimonials, optional budgets in create/edit/read, conservative identity/category/locality invitations, relevant regulated-category licence requirement, migration and unit test definitions and branch CI. Existing transaction, quote, referral and payout rules unchanged. No automatic assignments or charges. Missing free-text service areas suppress automatic invitations; marketplace browsing remains available. No availability or licence-scope inference. Same-tab unsubmitted request expires after one hour; cross-device re-entry required.

## Complete release gates
- Structured availability, durable invitation queue with retries/idempotency and fallback, no-match handling, cancellation recovery, notification preferences.
- Quote comparison, booking/rescheduling, appointment reminders, job timeline, payment and completion/receipt/review lifecycle.
- Safe photo/voice entry, rate limits, upload authorisation, private storage, responsive copy/design audit.
- Pro tools: quote templates, customers, invoices, calendar, booking links, analytics; My Home, saved pros, rebooking and maintenance; instant booking and price guidance feature-gated until validated.
- Self-service resolution, admin exceptions/health, funnel analytics, permissions audit and full staging E2E.

## Release and rollback
No merge/deploy until full scope and CI/staging gates pass. Record actual production deploy SHA (not necessarily main). Verify recoverable DB backup, schema and counts. Use Stripe test mode, non-production email/SMS. Never run destructive drizzle push; append explicit verified migrations to existing predeploy. Budget nullability preserves values; old UI may not display missing budgets correctly, so disable new missing-budget creation during rollback window or ensure old code compatibility. Never invent budget amounts. If release fails, stop new workflows, roll back to recorded working deployment, reconcile Stripe events and avoid blind DB restoration over new customer transactions.

## Durable matching implementation (development only)
Run `pnpm db:v2-matching` on a disposable staging database after the budget/referral migrations. Only after successful staging tests set SASKHANDY_V2_MATCHING=1; default is disabled. New requests are atomically queued in the job insert transaction. The existing quiet-hours reminder scheduler processes due waves of up to five distinct eligible providers at 0, 4 and 12 hours, then gives a truthful no-quote update after 24 hours (subject to scheduler cadence and quiet hours). Existing jobs are not backfilled or modified. In-app delivery is atomic; SMTP delivery retries are bounded but may duplicate an email after uncertain provider acceptance. No booking, selection, payment, or payout is automated by matching. Missing service areas and profiles prevent auto-invites. A quote arriving stops future waves; rejected quotes do not automatically restart matching yet. Feature flag off stops new runs and processing; existing queue rows persist. Admin health displays overdue runs and failed invitations; no guarantee of availability. Add tests for concurrent claims, job cancellation, late responses, SMTP timeouts and permissions before activation.

## Appointments (development only)
Apply `pnpm db:v2-appointments` to staging, then enable SASKHANDY_V2_APPOINTMENTS=1 only after testing. Appointment actions are restricted to the selected professional and homeowner on in-progress marketplace jobs. Two-party approval, proposal versions, professional-row locking and overlap checks guard confirmations. Rescheduling retains the previous confirmed time until approved. Cancellation affects only the appointment, never the job, payment or refund. In-app reminders are sent once per confirmed appointment within 24 hours, subject to scheduler cadence and quiet hours; no external appointment email/SMS yet. Pro invitation pause is respected by the durable matching worker when both flags are enabled; the legacy matching path is not yet integrated. Saskatchewan/Regina local-time input targets Saskatoon. Actual instant-booking slots, referral/Quick Quote appointments, cross-time-zone handling and integration/concurrency testing remain release gates.

## My Home (development only)
Apply db:v2-home to staging and enable SASKHANDY_V2_HOME=1 only after testing. Adds privately scoped property labels/cities, maintenance tasks with in-app due reminders, saved ID-approved professionals and completed marketplace job history. No home street addresses collected here. Saving a provider does not book them or bypass eligibility. Repeat direct booking, recurring maintenance, property deletion and account-deletion cleanup for V2 tables remain pending. No payment records changed. TypeScript now targets ES2022 and getDb returns its initialized non-null instance instead of a nullable global.

## Professional tools and request improvements (development only)
Apply db:v2-pro then enable SASKHANDY_V2_PRO=1 only after staging. Quote templates reuse work/pricing without copying contact fields, permissions, tokens or payment/referral state; users must review template free text for customer information before reuse. Customer history is derived from up to 500 existing owned quotes, grouped by normalized exact email or phone (never name alone); gross paid quote values are not payout or profit. Quote comparison uses existing quote amounts, messages and availability. Paid public quotes can be printed as payment records, not statutory tax invoices. Optional browser speech dictation requires consent, may use browser provider processing, and requires review. No audio stored by SaskHandy. Existing manual photo uploads remain; image recognition and secured upload overhaul still pending. Instant booking, direct repeat booking, cancellation/refunds, account-deletion cleanup, full page audit and staging remain outstanding.

## Privacy and type-safety review
Public professional endpoints use an explicit public-field allowlist; identity, insurance, criminal-record and licence files, contact email, notes, payout accounts and earnings are omitted. Uploads now require a valid session and check permitted MIME types and file signatures; this is not yet full private document storage. Existing public Cloudinary document URLs need a separate access audit and migration, and job photo visibility and deletion retention need review. Type checks are mandatory; do not suppress strict checks. The existing Stripe API version is preserved intentionally and must be integration-tested. The unused legacy OAuth callback returns an explicit unsupported response, not a fabricated login. My Home entry is hidden when disabled.

## Database-backed integration gate
CI creates a separate empty localhost-only MySQL database and refuses schema setup unless GitHub Actions and the exact integration database name are present. It tests actual queued matching, email recovery and duplicate prevention, quote/no-quote/closed transitions, admin and homeowner access, two-party scheduling/overlap/cancellation/reminders, property and maintenance isolation, saved profiles and professional quote template ownership. External providers remain mocked. This is separate from real Stripe sandbox and browser E2E testing.

## Instant booking (development only)
Apply db:v2-booking, then enable SASKHANDY_V2_BOOKING=1 alongside appointments only after full staging checks. Saskatoon pilot: three deliberately limited non-regulated service scopes. Professionals publish exact time, scope and total including taxes. Customer reservation atomically creates existing job, accepted quote, payment record and appointment, with the existing marketplace fee. Checkout still uses Stripe. No work before payment confirmation. Unpaid hold expires after 20 minutes only if checkout has not started; after payment initiation, release requires payment reconciliation. Expired slots are withdrawn, not silently relisted. Published-price guidance uses at least three distinct eligible providers for the same service; otherwise no range. Not a general estimate. No automatic charging, refunds or payout. Feature activation and Stripe sandbox concurrency/expiry tests are mandatory. Keep booking flag on while outstanding reservations exist.

## Payment and document hardening
Signed Stripe events and direct quote confirmation now share transactional reconciliation: exact stored intent ID, CAD amount, amount received and participant metadata are checked. Late failure events cannot reopen active/completed jobs or paid/completed quotes. Payment intent creation uses stable per-attempt idempotency keys. Quotes accepted before expiry stay payable; legacy expired or inconsistent records require reconciliation. New verification documents use authenticated Cloudinary raw assets behind an owner/admin-only download endpoint. Existing public document URLs are not migrated by this code; storage credentials and an actual migration/access test are required. No real payment or payout was sent. Integration tests simulate verified Stripe intents, concurrent slot reservations and cancellation before checkout.

## Browser smoke gate
Production static route allowlist now recognizes /book and /my-home. Browser tests use the isolated CI database with synthetic accounts and a local server, fake Stripe key, blocked external browser requests, and screenshots at 390px and 1440px. They check representative guest, homeowner, professional and admin pages, direct HTTP route loads, JS errors and horizontal overflow. This is not a substitute for full manual visual acceptance or real provider integration.
