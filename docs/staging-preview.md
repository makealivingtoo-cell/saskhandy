# Free Render staging preview
Deploy Dockerfile.staging on a free web service from saskhandy-2.0 with SASKHANDY_STAGING_PREVIEW=1, a random STAGING_ACCESS_PASSWORD (at least 24 characters), and all V2 feature flags enabled. The container creates a fresh loopback-only MariaDB database with generated MySQL-compatible schema and fictional fixtures; no production database or credentials are used. /__preview provides password-protected role selection, not production authentication; /__preview-health is a non-sensitive health endpoint. Production mode is unaffected when preview flag is absent. No real Stripe, mail, SMS, AI or cloud-storage credentials. Real integrations and persistence are deliberately not validated by this free preview. Data resets on instance restart/sleep/redeploy. Staging-only build omits SEO prerendering. Never enter real customer/verification data. Render free memory may constrain this two-process preview; check deployment logs before claiming live. This configuration does not replace a persistent staging database or full provider acceptance testing.
